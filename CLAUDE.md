# Triki: браузерное демо событий

## Цель

Сделать браузерное демо (Web Bluetooth + TypeScript), которое показывает, какие события можно предсказуемо ловить с Żabka Triki. Итеративно: добавляем детектор, смотрим вживую, оцениваем надёжность, идём дальше.

Потенциально позже: macOS-утилита (меню-бар). Для неё варианты: Python + bleak + rumps (быстро) или Swift + CoreBluetooth (надёжнее для фона). Логику детекторов держим отдельно от BLE-слоя, чтобы её можно было перенести.

## Что такое Triki

- Коллекционный BLE-жетон Żabka в форме пивной крышки (капсля). Продаётся в Żabka (около 70 zł, по акциям от 1 zł).
- Железо: SoC nRF52810 (Cortex-M4), IMU LSM6DSL (6 осей: акселерометр + гироскоп), светодиод, кнопка.
- Магнитометра нет. Значит yaw (поворот вокруг вертикали) медленно дрейфует.
- Реверс-инжиниринг сделан сообществом. Официального SDK нет.

## BLE-интерфейс (из публичных репозиториев, проверить на устройстве)

- Реклама: имя `TRIKI <serial>` или `Triki <serial>`, random static адрес, сервис `0x0001`. Ищем по имени, содержащему "triki" без учёта регистра.
- Данные идут по Nordic UART Service (NUS).
- Для старта потока IMU нужна команда. Её описание и 14-байтовый формат кадра лежат в репозитории Flopsstuff/triki: `docs/guide/ble-protocol.md` и `docs/guide/imu-streaming.md`. Не угадывать байты, читать оттуда.
- Кадры приходят пачками (burst), по несколько штук подряд. Временем сэмпла считать время прихода notification, а не внутренние метки.
- Частота настраивается: 26 / 52 / 104 / 208 / 416 Гц. Есть переключение зелёного светодиода.
- Есть чтение уровня батареи (см. Python-драйвер).

## Что можно детектить, а что нет

Надёжно:
- ориентация (гироскоп + Madgwick), наклон
- линейное ускорение по X, Y, Z (после вычитания гравитации по ориентации)
- направленные рывки и толчки по осям
- встряска, удар, падение, бросок, момент невесомости в полёте
- покой и движение
- вращение (спин) и его направление
- простые жесты: свайп, взмах, подбрасывание, переворот (flip)

Нельзя (не обещать в UI):
- абсолютная позиция и точное смещение. Двойное интегрирование ускорения уплывает за секунды. Допустима только грубая оценка коротких жестов с обнулением скорости в покое (ZUPT), порядка 10-30 см.
- стабильный yaw без внешней коррекции.

## План итераций

1. Подключение, парсер 14-байтовых кадров, живые графики сырых данных (acc, gyro) с выбором частоты.
2. Ориентация (Madgwick), 3D-визуализация, кнопка re-zero heading.
3. Линейное ускорение в мировых осях, графики по X, Y, Z.
4. Детекторы событий по одному, каждый с порогами в UI и логом срабатываний:
   - покой / движение
   - рывок по оси (+X, -X, +Y, -Y, +Z, -Z)
   - встряска
   - удар / падение
   - бросок и свободное падение
   - вращение (направление, обороты)
   - flip / переворот
5. Для каждого детектора записать: порог, задержка, ложные срабатывания, при какой частоте стабилен. Вывод оформить таблицей "событие : надёжность : условия".
6. Запись сессий в CSV и повтор (replay) для отладки детекторов без устройства.
7. Опционально: простое распознавание жестов, затем перенос ядра в macOS-утилиту.

## Стек и ограничения

- TypeScript, Vite, без тяжёлых фреймворков. Нужен только Chrome или Edge (Web Bluetooth). Safari не подойдёт.
- Web Bluetooth требует HTTPS или localhost и жеста пользователя для подключения.
- Ядро (парсер, фильтр, детекторы) писать как чистые функции без зависимости от DOM и BLE, чтобы покрыть тестами и потом перенести.
- Зависимости минимум. Протокол и Madgwick написать самим или взять только `triki-controller` (npm, без зависимостей) как референс.

## Референсы

- Flopsstuff/triki: https://github.com/Flopsstuff/triki (Web Bluetooth клиент, Madgwick, протокол). Основной референс, демо уже проверено вручную.
- Piwencjusz/zabka-triki-hardware: https://github.com/Piwencjusz/zabka-triki-hardware (железо, BLE, OTA)
- Wojtekb30/unofficial-triki-api-py: https://github.com/Wojtekb30/unofficial-triki-api-py (Python, bleak)
- Maku-hub/TrikiScope: https://github.com/Maku-hub/TrikiScope (TUI, жесты, CSV)
- bleak (для Python-версии): https://github.com/hbldh/bleak

Эти проекты любительские и мной не аудированы. Использовать как документацию, код не копировать без чтения. Готовые бинарники (.exe) не запускать.

## Правила безопасности

- Только чтение данных. Не прошивать устройство и не лезть в SWD: у пользователя одно устройство.
- Не отправлять на устройство команды, которых нет в документации протокола.
- Серийник и BLE MAC не коммитить в репозиторий и не печатать в логах по умолчанию.
