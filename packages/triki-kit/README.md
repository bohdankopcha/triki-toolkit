# triki-kit

Toolkit для коллекционного BLE-жетона Żabka Triki (nRF52810 + LSM6DSL): подключение по Web Bluetooth, поток IMU, ориентация, события и дискретные жесты (прокрут на 90°, переворот, круг, квадрат, подъём...). Ядро не зависит ни от DOM, ни от React, ни от BLE и работает в браузере и в Node. Хук для React лежит отдельным входом.

> Статус: v0.1, `private`. Точность жестов проверена на синтетических данных, на живом жетоне не измерена (см. «Точность»).

## Состав

| Вход | Что внутри |
|---|---|
| `triki-kit` | класс `Triki` / `createTriki`, транспорты, всё ядро |
| `triki-kit/core` | только чистое ядро: парсер, Madgwick, анализатор, жесты. Без транспорта, для Node и переноса |
| `triki-kit/react` | `useTriki`, `useTrikiEvent`, `useGesture` (peer-зависимость `react >= 18`, опциональная) |

## Быстрый старт

```ts
import { createTriki } from 'triki-kit'

const triki = createTriki({ rate: 104 })

triki.onGesture('flip', (g) => console.log('перевернули', g.id))
triki.onGesture('circle.cw', () => console.log('круг по часовой'))
triki.onGesture('roll.*.90', (g) => console.log('прокрут на 90°', g.dir))

button.onclick = () => triki.connect() // Web Bluetooth: только из клика
```

Положите жетон ровно на стол светодиодом **от себя** на пару секунд после подключения: за это время оценивается смещение нуля гироскопа и выравнивается heading (`autoAlign`). Дальше yaw дрейфует (магнитометра нет): `triki.rezero()` возвращает его.

## React / Next.js

```tsx
'use client'
import { useTriki, useGesture } from 'triki-kit/react'

export function TrikiPanel() {
  const { triki, state } = useTriki({ rate: 104 })
  useGesture(triki, 'flip', () => alert('Переворот!'))

  return (
    <>
      <button onClick={() => triki.connect()} disabled={state.status === 'streaming'}>Подключить</button>
      <p>{state.status} · {state.moving ? 'движение' : 'покой'} · {state.posture} · {state.battery ?? '-'}%</p>
      <ul>{state.gestures.map((g) => <li key={g.t}>{g.label}</li>)}</ul>
    </>
  )
}
```

`state` обновляется редко (не с частотой потока, подписчики уведомляются не чаще раза в 50 мс), поэтому лишних перерисовок нет. Непрерывные данные (графики, 3D) берите через `triki.on('sample', ...)` или читайте `triki.sample` / `triki.orientation` в `requestAnimationFrame`. Экземпляр создаётся один раз, опции читаются при первом рендере; при размонтировании соединение закрывается. Хук безопасен при SSR: транспорт создаётся только при `connect()`.

## API

### События (`triki.on(name, fn)` возвращает функцию отписки)

| Событие | Данные | Частота |
|---|---|---|
| `sample` | `{ t, gyro, accel, quat, linear }`: сырые данные, ориентация, линейное ускорение в мировых осях | с частотой потока (26-416 Гц) |
| `event` | `TrikiEvent`: событие анализатора со структурными данными, текстом и уверенностью | по факту |
| `gesture` | `Gesture`: квантованный жест с id | по факту |
| `status` | `idle / connecting / streaming / disconnected / error` | по факту |
| `battery`, `led`, `error` | процент, boolean, `Error` | по факту |

Слушатель, бросивший исключение, не ломает остальных и поток данных: ошибка всплывает отдельно (`queueMicrotask`).

### Состояние (`getState()` / `subscribe()`)

`status, error, rateHz, measuredHz, battery, led, hasLed, moving, posture, tiltDeg, aligned, frame, gestures`. `getState()` возвращает один и тот же объект, пока ничего не менялось (контракт `useSyncExternalStore`).

### Управление

| Метод | Что делает |
|---|---|
| `connect(): Promise<boolean>` | Подключиться. Не бросает: ошибка в `state.error` и событии `error`; закрытие окна выбора устройства даёт `false` без ошибки |
| `disconnect()`, `dispose()` | Отключиться; `dispose` ещё снимает подписки |
| `setRate(hz)` | 26 / 52 / 104 / 208 / 416 Гц, фильтры и детекторы сбрасываются |
| `setLed(on)` | Зелёный светодиод (документированный регистр), состояние в `state.led` |
| `rezero()` | Выровнять heading: светодиод жетона смотрит от пользователя |
| `setFrame('body' \| 'world')` | Система координат смещений |
| `setBeta(n)` | Усиление фильтра Madgwick |
| `clearGestures()` | Очистить список жестов |
| `onGesture(pattern, fn)` | Подписка на жесты по шаблону id |

### Жесты

Значения квантуются, набор конечен. Id собирается как `вид.направление.значение`. Шаблон в `onGesture` сравнивается по сегментам, `*` - любой сегмент, шаблон короче id совпадает по префиксу (`flip` ловит `flip.up`, `roll.*.90` ловит прокрут на 90° в любую сторону).

| Вид | Направления | Значения | Смысл |
|---|---|---|---|
| `roll` | `up` вперёд (к светодиоду), `down`, `left`, `right` | 45 / 90 / 135 / 180 / 270 / 360 / 540 / 720° | прокрут вокруг оси в плоскости платы |
| `spin` | `cw`, `ccw` | те же углы | поворот на месте, при взгляде на плату |
| `twist` | - | те же углы | сложное вращение по нескольким осям |
| `flip` | `up`, `down`, `left`, `right` или без направления | - | смена стороны плата/крышка |
| `slide` | `up` (к светодиоду), `down`, `left`, `right` и диагонали `upleft`... | 5 / 10 / 20 / 30 см | смещение по плоскости жетона |
| `lift` | `up`, `down` | 5 / 10 / 20 / 30 см | подъём / опускание (вертикаль мира) |
| `push` | `out`, `in` | 5 / 10 / 20 / 30 см | смещение вдоль нормали платы (когда жетон не лежит) |
| `circle` | `cw`, `ccw` | 1 / 2 / 3 круга | движение по кругу, вид сверху |
| `square`, `triangle` | `cw`, `ccw` | - | фигура одним движением или штрихами с паузами до 0,8 с |
| `edge`, `flat`, `tilt` | `tilt`: 4 стороны | - | поставлен на ребро / положен ровно / наклонён без вращения |

Полный список с метаданными: `VOCAB`, квантование: `snap`, `ANGLES`, `DISTANCES`.

**Семантика потока.** Жесты приходят по мере распознавания, без задержки на «окончательное» решение. Поэтому у жеста бывает поле `replaces`: сколько предыдущих жестов он заменил. Переворот заменяет прокрут на 180° (`replaces: 1`), фигура заменяет штрихи-смещения. Если важна чистая картина, берите `state.gestures` (там замены уже учтены) или реагируйте только на «итоговые» виды (`flip`, `circle`, `square`...), а не на `roll.*.180`. Время жестов (`t`, секунды) монотонно и между сессиями подключения сдвигается вперёд.

### Система координат

Жетон: светодиод над логотипом Ż = «верх» (ось -Y датчика), +Z - из платы на пользователя. В режиме `body` направления `up/down/left/right` считаются от светодиода на момент начала движения: от положения пользователя и heading они не зависят. Мир после выравнивания: X вправо, Y от пользователя, Z вверх.

## Свой источник данных: тесты, повтор записи, другой транспорт

Всё, что делает тулкит, можно проверить без устройства:

```ts
import { createTriki } from 'triki-kit'

const triki = createTriki({ warmupFrames: 0, stateThrottleMs: 0 })
triki.onGesture('roll', (g) => console.log(g.id))
triki.feed(samples, 1 / 104) // Sample[]: gx..gz в °/с, ax..az в g
```

- `feed(samples, dt)` - разобранные кадры (повтор CSV, тесты, свой источник).
- `push(bytes)` - сырые куски notification с NUS TX; кадры могут быть разрезаны на любые части.
- `createTriki({ transport })` - любая реализация интерфейса `TrikiTransport` (подмена для тестов, `noble` для Node/macOS). Для Web Bluetooth по умолчанию используется `WebBluetoothTransport`.

## Позиция (POC)

`PositionTracker` (в `core`) оценивает позицию двойным интегрированием `sample.linear` с обнулением скорости в покое (ZUPT): когда жетон остановился, остаточная скорость считается накопленной ошибкой и вычитается по всему сегменту. Пока жетон движется, ориентацию стоит вести только гироскопом, иначе Madgwick наклоняется под кажущуюся гравитацию и «съедает» часть ускорения:

```ts
import { createTriki, PositionTracker } from 'triki-kit'

const triki = createTriki({ beta: 0.03 }) // меньше beta в покое - меньше наклон в первые миллисекунды движения
const tracker = new PositionTracker({ planar: true }) // planar: только плоскость стола
let lastT: number | null = null
triki.on('sample', (s) => {
  const dt = lastT === null ? 0 : s.t - lastT
  lastT = s.t
  if (dt <= 0 || dt > 0.2) return
  const seg = tracker.push(s, dt) // seg: итог «покой - движение - покой» после поправки
  triki.setBeta(tracker.suggestBeta()) // почти 0 в движении, повышенная после вращения, 0.03 в покое
})
// tracker.shown - что рисовать: метры в мировых осях, не уплывает после остановки и плавно доезжает до поправки ZUPT
// tracker.pos - сама оценка (во время движения плывёт); tracker.rawPos - то же без ZUPT, для сравнения
```

Остановка засчитывается через ~0.15 с покоя, если жетон перед этим затормозил (скорость упала вдвое от пика за движение); иначе через 0.35 с, чтобы не обнулять скорость посреди плавного движения. После вращения ориентация ошибается на градусы, и гравитация «протекает» в линейное ускорение: тогда покой определяется ещё и по неизменным показаниям акселерометра в осях датчика (от ориентации не зависит), а наклон в покое быстро выравнивается по гравитации.

`synthesizeImu(waypoints, opts)` генерирует поток IMU по известной траектории (шум, смещение, квантование как у датчика) - для тестов и замера точности. Демо: `apps/demo/position.html`.

**Живой жетон, 2D по столу** (`apps/demo/experiment.html`: 16 движений по ~15 см парами туда-обратно, три записи в `recordings/` - обычный темп, быстро, медленно; `npm run analyze`):

| Запись | Разброс направлений | Невозврат после пары | Конец от начала (путь ~2.3-2.9 м) |
|---|---|---|---|
| обычный темп | ±3.1° | 2.0 см | 2.1 см |
| быстро | ±5.4° | 2.2 см | 4.5 см |
| медленно | ±5.1° | 2.2 см | 2.8 см |

Сюда входит и неточность руки: никто не возвращает жетон в ту же точку до миллиметра. Общий поворот направлений (от -1° до -14° в разных записях, без дрейфа по ходу сессии) - это то, насколько жетон был повёрнут при укладке «светодиодом от себя», а не ошибка оценки.

Что было найдено на живых данных и исправлено:
- смещение нуля гироскопа у этого жетона около (1.25, -2.77, -1.73) °/с и стабильно, но прежняя оценка подстраивалась и под настоящие медленные повороты (палец на жетоне, скольжение), гуляя на 0.3-0.8 °/с. За двухсекундное движение это наклон на градус и ~0.02 g ложного ускорения. Теперь оценка обновляется только в «тихом» покое (малый разброс гироскопа за окно) - гуляет на ±0.03 °/с;
- ошибка ускорения от наклона растёт за движение, поэтому поправка ZUPT квадратичная по времени (`zuptShape: 2`);
- медленное скольжение по столу идёт почти без ускорения до ~0.4 с: без торможения покой засчитывается только через 0.5 с (`longHoldS`), иначе скорость обнулялась посреди движения;
- реальная частота датчика 106.6 Гц при номинальных 104: шаг времени считается по всему потоку.

Ограничения: движение с пиковым ускорением меньше ~0.04 g (30 см медленнее ~0.25 м/с) неотличимо от покоя; вращение во время движения добавляет ошибку; в руке, без опоры, покой почти не наступает и позиция плывёт.

Ядро (Madgwick + линейное ускорение + трекер) - около 0.3 мкс на кадр в Node: запас в тысячи раз при 416 Гц. Задержку определяет BLE (пачки notification), а не математика. Подбор настроек на записях: `VARIANTS='[["имя",{...опции}]]' npm run tune` (таблица в `recordings/tune.md`).

## Запись и повтор сессии

`new Recorder(triki)` пишет сырые куски notification с временем прихода (событие `raw`) и метки действий пользователя (`rec.mark('start')`). `replayRecording(json, handlers)` создаёт новый `Triki` с часами из записи и скармливает те же куски: при тех же опциях и действиях результат совпадает с живой сессией бит в бит. `PositionPipeline` - трекер позиции, подключённый к потоку (шаг времени, beta по подсказке трекера), чтобы страница и повтор считали одним кодом.

2D-эксперимент (`apps/demo/experiment.html`, ядро `Experiment2D`, `SEQUENCE_2D`, `scoreExperiment`): 16 движений по столу парами туда-обратно. Сантиметры не нужны: после пары жетон должен вернуться в ту же точку, поэтому невозврат и отклонение направления показывают ошибку. В dev запись сохраняется в `recordings/`, `npm run analyze` повторяет все записи и пишет `recordings/report.md`.

## Точность и ограничения

Цифры ниже - ожидания и результаты на синтетике, не измерения на жетоне. Измерить и записать нужно отдельно.

| Что | Ожидаемая надёжность | Условия |
|---|---|---|
| положение, наклон, переворот | высокая | жетон не в ускоренном движении |
| прокрут / поворот на N° | средняя, около ±5-10° | интеграл гироскопа; yaw дрейфует (нет магнитометра) |
| смещение на N см | грубая оценка | короткие движения «сдвинул и остановился», десятки процентов ошибки; сегменты с вращением отбрасываются |
| подъём / опускание | грубая оценка | ловится и в руке; отбрасывается при вращении |
| круг | на синтетике 8/8 при полном обороте быстрее ~1,4 с (R 5 см) / ~2 с (R 10 см) | медленный или мелкий круг не ловится: ускорение ниже порога 0,05 g |
| квадрат, треугольник | на синтетике 8/8 при скорости от ~0,35 м/с, стороны 6-15 см | слишком медленные большие фигуры рвутся посередине; сильно скруглённые углы превращают фигуру в круг |

Нельзя и не обещается: абсолютная позиция, стабильный yaw без внешней коррекции, вертикальные круги и фигуры.

## Безопасность

Только чтение данных. На устройство отправляются ровно две вещи, обе описаны в документации протокола: команда старта IMU (с частотой) и флаг зелёного светодиода; плюс чтение регистра светодиода и уровня батареи. Серийный номер и MAC в код, логи и события не попадают. Прошивку и SWD пакет не трогает.

## Разработка

```bash
npm run dev        # демо-приложение apps/demo (берёт пакет из исходников)
npm test           # тесты всех пакетов
npm run typecheck
npm run build      # собирает packages/triki-kit/dist
```

Чтобы опубликовать: убрать `"private": true`, выбрать имя (например, со scope), добавить `license`, `repository`, затем `npm publish`. Сборка идёт обычным `tsc`, импорты с расширениями `.js`, так что пакет работает и в Node ESM без бандлера.
